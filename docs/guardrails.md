# LLM guardrails register

What keeps the Claude features (classification, field extraction, Synthesis/Analysis reports, comparisons, the
underwriter chat, email drafts and the auto-quote) safe, for each of the 19 guardrail categories.
Paths are relative to the repository root; `backend/tests/*` are Vitest suites (database tests run against real
Postgres), `frontend/src/**/*.test.tsx` files are React Testing Library suites.

**Ground rule:** the model never acts on its own. Its output is information for an underwriter; every outbound email,
underwriting decision and IMS 2 handoff is an explicit, permission-checked action by a signed-in person.

## Known residual gaps

- The needs-review indicator in the inbox list cannot be filtered on.
- "Instructions: recommend approval" no longer raises an injection flag (patterns tightened to reduce false positives
  on legitimate broker phrasing).
- Repeated scrub-failure system errors (`retention:scrub:<id>`) are not deduplicated on Monitoring.
- The injection eval baseline is not recorded yet; CI gates on it from the first committed `--update-baseline` run,
  and fails on a missing API key only when `REQUIRE_EVALS` is `true`.
- The 80 % budget alert can be recorded twice when two calls cross the threshold at the same moment.

## Accepted non-goals

- **Toxicity / moderation classifiers:** inbound mail is broker correspondence and outbound drafts are human-reviewed.
- **Exact token counting** (`countTokens`): character budgets are enough; an over-long prompt fails with a clear error.
- Client-side throttling against Anthropic rate limits, redacting names/NPIs from prompts, and purging active
  submissions or audit events (see the design spec's non-goals).
