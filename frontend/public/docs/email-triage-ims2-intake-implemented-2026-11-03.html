1Summary

The email-triage app (separate service, own database) can now push an accepted Intake Draft into IMS 2. IMS 2 turns it into an open Policy Log record under exactly the same rules as a record typed in on the screen, and shows a “From email triage” card on that record.

Three machine-to-machine endpoints, all under /api/intake, authenticated with Authorization: Bearer <INTAKE_API_TOKEN> (no browser session):

EndpointPurpose
GET /api/intake/lookupFind an existing insured / broker before drafting (avoid duplicates)
POST /api/intake/draftsAccept a draft → create insured (optional) + Policy Log record
GET /api/intake/drafts/:draftId/statusLive state of the record a draft created

2Backend

2.1 New route — artifacts/api-server/src/routes/intakeDrafts.ts

Auth gate (requireIntakeToken)

  • INTAKE_API_TOKEN unset → 503 (feature off).
  • Missing / wrong token → 401. Compared with timingSafeEqual.

GET /intake/lookup

  • Query params (at least one): npi, email, licenseNumber (exact, case-insensitive), name (fuzzy Jaro-Winkler ≥ 0.8), brokerCode (exact brokers.broker_id), brokerName (fuzzy on full + short name, plus “contains” match for ≥ 3 chars, score 85).
  • Returns { insureds, brokers }, max 10 each, ranked by number of inputs matched, then score. Each hit has matchedOn and score.
  • Insured projection leaves out taxid and dob. Brokers include active flag.

POST /intake/drafts — one transaction

  1. Create the insured (with optional locations / contacts, first of each = primary) or link an existing one by insuredId.
  2. Create submission + submissions_details + policy_log_created audit.
  3. Insert intake_drafts row + intake_draft_accepted audit.

Rules enforced:

  • Body validated against a zod contract; contractVersion must be 1.
  • actingUserEmail must be an active IMS 2 user with policy-log:create (+ insured:create when creating an insured). Optional INTAKE_DEFAULT_USER fallback for reviewers with no IMS 2 account (reviewer email kept in audit; deactivated users still refused).
  • Broker must exist and be active.
  • policy.brokerId / brokerName / primaryInsuredId / insuredId are reserved (set from the broker / insured sections) → 400.
  • Locations / contacts only allowed with insured.create — a draft never changes an existing insured. Max 20 each, validated with the Insured screen’s validators.
  • Same policy rules as POST /policy-logs (no policyNumber, starts open, term rules, no endorsements, binder status list, etc.). A rule failure rolls back the insured it would have created.
  • Idempotent on draftId: same draftId + draftVersion → 200 with the original submission (replayed: true); a different version → 409. Concurrent resends handled via the PK unique violation.
  • ratingIndication / setupProposal are stored only on the draft row — never written to the submission, never read by the bind gate.

GET /intake/drafts/:draftId/status

  • Returns submission id/number, workflow status, policy number, bound, posted to bordereaux, deleted, dates, premium, binder status, and the deep link url. 404 if never accepted.

2.2 Refactor — routes/policyLogs.ts

  • POST /policy-logs split into two exported helpers so the intake route reuses them:
    • checkPolicyLogCreate(body) — all create rules, no DB access; returns the 400 body or a checked input.
    • insertPolicyLog(tx, input, actor, auditDetails) — inserts both tables + audit inside the caller’s transaction.
  • Behaviour of POST /policy-logs is unchanged.
  • GET /policy-logs/:id now also returns intake (provenance from intake_drafts, or null).

2.3 Other backend changes

  • routes/insureds.ts: coerceProfile and primaryName are now exported (reused by intake).
  • routes/index.ts: the three /intake/* routes are registered above requireAuth (they authenticate themselves).

4Frontend (Policy Log page)

  • components/rail/TriageCard.tsx — new right-rail card, shown only when record.intake is set:
    • Draft id / version, accepted date, “Open in triage ↗” link, “insured was created from this draft” note.
    • Suggestions list (rating indication + setup proposal) with per-row Apply and Apply all. Each row shows the current value and is marked In form, Locked, Calculated field, Not a single value or Not a Policy Log field when it can’t be applied.
    • Apply only stages the value as an unsaved edit and opens its stage — nothing is saved until the user saves the stage.
    • Field sources list with SourceChip (Extracted / Edited / Manual).
  • model/intake.ts — proposalRows() / findField(): maps proposal keys to Policy Log fields and decides applicability.
  • fields/FieldControl.tsx — shows the SourceChip next to a field’s label on triage-created records.
  • index.tsx — mounts <TriageCard /> between BlockingBind and RecordCard.
  • types.ts — RecordResponse.intake, IntakeProvenance, FieldSource.
